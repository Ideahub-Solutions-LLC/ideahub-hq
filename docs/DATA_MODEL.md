# Data model

Source of truth: `src/db/schema.ts` (Drizzle). Migrations: `drizzle/*.sql` (generated by `pnpm db:generate`, applied by `pnpm db:migrate` or automatically on first app start). IDs are prefixed random strings (`emp_…`, `tsk_…`); timestamps are ISO‑8601 UTC text for portability.

Every business table carries `workspace_id`. Secrets are never stored in any table — only env var *names*.

## Identity and access

| Table | Purpose |
| --- | --- |
| `workspaces` | Tenant boundary. `settings` JSON: product name, emergency stop flag/reason, branding accents. |
| `users` | People. `password_hash` (scrypt). |
| `workspace_members` | User ↔ workspace with `role` (owner/admin/manager/member). Unique per pair. |
| `sessions` | Server-side sessions; `id` is the SHA‑256 of the cookie token; `expires_at`. |

## Organization

| Table | Purpose |
| --- | --- |
| `departments` | Name, purpose, human manager, color token, office `layout` (col/row). |
| `employee_briefs` | Current structured operating brief, version, draft/approved status and reviewer. Edits invalidate review; only the reviewed body shapes chat instructions. Earlier bodies are not yet an immutable archive. |
| `employees` | The durable AI employee record. Separate JSON blocks: `personality` (style only), `authority` (allowed action types, forbidden list, review policy, max actions), `model_config` (provider, model, temperature, fallback, budgets). `status` draft/active/paused/archived, `seniority`, `config_version` (bumped on every change), `is_pilot`. |

## Skills and knowledge

| Table | Purpose |
| --- | --- |
| `skills` | Named procedure with owner, status (draft/review/approved/retired), `current_version`, optional `workflow_key` linking to executable code. |
| `skill_versions` | Immutable versions: instructions, inputs/outputs contract, required tools, required approvals, review status, change note, author. |
| `employee_skills` | Assignment. Only approved skills are included in prompts. |
| `knowledge_sources` | Approved company/department knowledge: type (document/note/url/meeting_record/procedure), content (treated as untrusted data), source ref, owner, review status (pending/approved/rejected/stale), version, last verified. Content edits bump the version and reset review. |
| `employee_knowledge` | Access grant. Retrieval only returns approved sources in this list. |
| `memory_proposals` | Queue of proposed memories (preference/fact/procedure/instruction) with source ref and review decision. |
| `memories` | Approved memories with scope, approver and source. Shown to the employee in its prompt. |

## Work

| Table | Purpose |
| --- | --- |
| `tasks` | Objective, status (queued/working/needs_approval/blocked/completed/paused/failed), priority, accountable human owner, requester, optional AI employee, `workflow_key` + `input`, progress, next action, blocked reason. |
| `task_steps` | Durable checkpoints per step (name, status, checkpoint JSON, timestamps). A task can resume without the model conversation. |
| `task_events` | Activity history: status changes, checkpoints, artifacts, approvals, receipts, errors, internal comments. |
| `artifacts` | Outputs: `draft_action_list`, `draft_status_summary`, `content_draft`, `note`, `message_draft`; status draft/reviewed/rejected/superseded; reviewer + note. Content artifacts capture the brief, source snapshots, configuration/skill evidence, copy and claim checks. |
| `messages` | Employee conversations (user/employee/system) with metadata (provider, model, sources cited, degraded flag). |

## Control

| Table | Purpose |
| --- | --- |
| `approvals` | One row per proposed action: `action_type` (review_draft / create_external_tasks / send_message / access_service / update_external_record), destination, connector, exact `payload` + `payload_hash`, context, status lifecycle (pending → approved/rejected/changes_requested/expired → executed/execution_unknown/execution_failed), decider, note, `idempotency_key` (unique), expiry. |
| `action_receipts` | Exactly one per idempotency key: connector, mode (demo/live), status (executing/succeeded/failed/unknown), external ref, result. |
| `connectors` | Per-workspace connection record: key, requested mode, owner, scopes, permissions (read/write/send), status detail, credential env var **names**. |
| `connector_grants` | Employee ↔ connector access with scopes, grantor, active/revoked. |
| `communication_events` | Inbound/outbound/internal messages with status received/draft/pending_approval/sent/**simulated**/failed. Demo connectors only ever write `simulated`. |
| `audit_events` | Append-only: actor (user or employee), action, entity, redacted data. |

## Economics and operations

| Table | Purpose |
| --- | --- |
| `usage_events` | Ledger: employee, task, provider, model, meter (model_tokens/connector_call/storage), units, estimated cost (nullable) + `cost_status` (estimated/unavailable/final), unique `event_key`. |
| `budgets` | Monthly limits per workspace or employee with alert threshold. |
| `jobs` | Durable queue: kind (task.run / employee.reply / approval.execute), payload, status, attempts, run_after, lock. |
| `workflow_runs` | Content execution attempts: workspace/task/employee/job, owning attempt, stage, heartbeat, start/finish/error and reserved cost. Unique per job + attempt. Drives confirmed-live office activity and conservative budget holds. |
| `provider_catalogs` | Workspace/provider access-check snapshot: model IDs, status, timestamp, credential fingerprint and generic diagnostic. No raw credential or provider response. |
| `mcp_servers` | Workspace-scoped Streamable HTTP endpoint, owner, credential variable name, enabled/configuration version and bounded discovered tool inventory. |
| `mcp_tool_grants` | Reviewed employee/tool assignments pinned to server configuration and tool definition hash; read/approval-required policy and revocation. Assignment does not enable invocation. |

## Migrations

```bash
# after editing src/db/schema.ts
pnpm db:generate --name describe_change   # writes drizzle/000N_describe_change.sql + snapshot
pnpm db:migrate                           # applies to DATABASE_URL
pnpm test                                 # tests run migrations against :memory:
```

Commit the generated SQL and `drizzle/meta/*`. Never edit applied migrations; add a new one.

## Sample data

`pnpm db:seed` creates one fictional workspace (`IdeaHub HQ`): 5 fictional users, 6 departments, 7 AI employee profiles (only **Harper** active), 4 skills, 6 knowledge sources (approved / pending / stale examples), 2 memory proposals + 1 approved memory, 6 connectors (Demo / Disconnected / Planned), budgets, 7 human tasks, and then **runs the real pipeline**: a meeting-actions task (reviewed, with a pending follow-up proposal to the demo task system), a weekly-summary task (awaiting review), and one conversation with Harper. All names, clients and meetings are invented.

To change the fictional accounts, edit `src/db/demo-users.ts` and `src/db/seed.ts`, then `pnpm db:reset && pnpm db:setup`.

## Authentication additions (local P0)

`auth_rate_limits` holds hashed global authentication buckets, attempt counts and expiry milliseconds. `password_resets` holds a recovery-code hash, user, authorizing workspace and expiry. These are global authentication support records (users/sessions span workspaces); recovery issuance verifies the workspace and role in the service. Migrations: `0001_auth_recovery.sql` and `0002_recovery_issuer.sql`. Recovery codes also record their issuer so later permission changes are enforced at redemption.

## Shared work areas

Migration `0005_workspace_organization` adds `work_records`, `drive_blobs` and `app_installations`. Work records use validated schemas for folder/file/event/company/contact/deal/content/mail, optimistic edit versions and recoverable archives. Workspace references are checked in services. Scopes filter shared records; they are not team-level access controls. Binary files are SQLite blobs with service-enforced limits. App installations are setup intent records, not credentials or live connector grants. See [Workspace organization](WORKSPACE_ORGANIZATION.md).
